# Бенчмарк OCR

Какая система OCR лучше читает русский и английский текст на фото. Ноутбук с графиками и выводами: [`ocr.ipynb`](ocr.ipynb).

Поиск по тексту работает так: OCR превращает картинку в текст при индексации, а `ocrQuery` ищет слова в нём как подстроки. Поэтому главная метрика — **доля слов, видимых на фото, которые нашлись в распознанном тексте** (word recall). Дополнительно считается CER по лучшему совпадающему фрагменту (фоновый текст на фото ошибкой не считается).

## Итоги

| Система | Слова, синтетика ru | en | Слова, реальные фото | Лишних слов на фото без текста | мс на картинку (6 потоков) |
| --- | --- | --- | --- | --- | --- |
| **PP-OCRv5 mobile + eslav** (в приложении) | 0,944 | 0,954 | 0,68 | 2,3 | 1231 |
| PP-OCRv5 mobile + cyrillic v5 | 0,947 | 0,954 | 0,55 | 2,2 | 1319 |
| PP-OCRv5 **server** det + eslav | 0,998 | 0,983 | 0,64 | 3,2 | 11789 |
| PP-OCRv5 det + cyrillic v3 (старый) | 0,407 | 0,804 | 0,41 | 2,7 | 1166 |
| EasyOCR (ru + en) | 0,929 | 0,847 | 0,56 | 3,1 | 2447 |

Вывод: текущая система — разумный выбор. Серверный детектор лучше читает повёрнутый текст, но в 10 раз медленнее и на реальных фото не лучше. EasyOCR вдвое медленнее и слабее на английском. Старый распознаватель v3 заметно хуже. Общее слабое место — стилизованные вывески магазинов (на них все системы находят слова только на части фото). Подробности и оговорки — в конце ноутбука.

## Данные

`make_dataset.py` собирает набор (`data/labels.json` лежит в репозитории, картинки в `data/images/` нет, они воспроизводятся):

- **150 синтетических картинок** 1024×768: русские и английские фразы на однотонном фоне и на реальных фото (фото берутся из кэша Crossmodal-3600 из CLIP-бенчмарка), пять уровней сложности — `clean`, `photo`, `small`, `rotated`, `degraded`; эталонный текст известен точно. Шрифты берутся из `C:/Windows/Fonts` (другой путь — `--font-dir`);
- **12 реальных вывесок и знаков** и **10 «досок»** из `test-images` (их скачивает `backend/scripts/fetch_test_images.py`); ключевые слова реальных фото размечены вручную в `real_labels.json`;
- **10 фото без текста** для подсчёта лишних слов.

Реальных фото мало: одно фото весит около 8 п.п., поэтому небольшие различия между системами на них ненадёжны.

## Как запустить

Своё окружение (PaddleOCR и EasyOCR), отдельно от CLIP-бенчмарка:

```bash
cd bench/ocr
uv sync
uv run python make_dataset.py                         # данные
uv run python ocr_bench.py run --threads 2            # распознавание всеми системами (кэшируется)
uv run python ocr_bench.py speed --threads 6          # скорость на 30 картинках, запускать на свободной машине
uv run jupyter nbconvert --to notebook --execute --inplace ocr.ipynb
```

Полный прогон `run` занял около полутора часов на CPU при двух потоках, из них около 50 минут — серверный детектор. Системы задаются в `SYSTEMS` в `ocr_bench.py`, новую можно добавить в `make_engine`. Результаты распознавания лежат в `results/raw_preds/`, сводка — в `results/summary.csv`.

Настройки PaddleOCR такие же, как в `backend/src/utils/ocr.py` (без поворота, выпрямления и классификации строк, CPU).
